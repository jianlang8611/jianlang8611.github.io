# Human evaluation

Open [the online review index](https://jianlang.org/personaedit/human-evaluation/) or [index.html](index.html) locally. All source images and visual references are included, so the review pages work without external image hosts.

1. Choose a persona and inspect its basic information and editing profile.
2. Open your assigned group A (001–050) or B (051–100). Page 1 contains the reviewer instructions and required reviewer name; the name is used in JSON filenames. Click start to open the first persona on page 2, then complete each persona and click Next. You can return to the instructions and resume the same persona.
3. Read the persona and check for embedded editing intent. For every task, inspect leakage/shortcuts and irresolvable ambiguity/evidence gaps against the source, profile and underlying annotations.
4. Rewrite the **upper personalized editing request**, not the profile or lower operation description. The original upper request appears immediately above each rewrite box. Before rewriting, read the persona's basic information and relevant personal knowledge. Put yourself in that person's role and use the current image and request context to express the same editing intent as they naturally would. Natural expression is the goal; length follows the intent and context. Every request requires a human rewrite, including requests judged acceptable. Preserve personalization and hidden values/locations; do not copy the original verbatim, invent facts or use AI to write it. Confirm the rewrite's fidelity.
5. Fill all ten rewrites and both judgments on the current persona, then click “下一页”; your work is saved automatically. An issue or uncertainty requires an explanation. The final persona has “完成本组并导出JSON”, which requires all 50 personas. Individual complete reviews and drafts can also be exported; drafts can be imported to resume.
6. Send the downloaded JSON as an attachment to [jian_lang@std.uestc.edu.cn](mailto:jian_lang@std.uestc.edu.cn). Filenames include the reviewer name. The first-page instructions also offer an export of the currently completed portion. Keep a copy.

Comments are saved in the current browser, separately for each persona. They are not automatically uploaded. Returned files are stored under `results/`.

Schema 2.0 exports include `protocol_version`, `persona_id`, `group_id`, `dataset_revision`, UI provenance, required reviewer name, reviewer ID and export time. The name also appears in each JSON filename. Each of ten task rows stores source hashes, `human_instruction`, two judgments (`leakage`, `solvability`), an explanation and fidelity confirmation. `profile_review` records the persona-level check. `review_status` distinguishes complete reviews, drafts and complete batches; `group_complete` identifies a complete 50-persona batch. Complete means the required fields were filled, not that the sample passed all judgments. Earlier drafts remain importable; their removed naturalness field is not required or exported. Only returned files belong in `results/`; draft examples and internal exploratory feedback are not submissions.
