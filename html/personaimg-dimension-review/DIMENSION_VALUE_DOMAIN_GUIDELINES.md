# Dimension Value-Domain Guidelines

本文件为后续维度值域构建和人工审核的约束，尤其适用于“手持物 / 工具 / 设备”这类
容易把多个轴混在一起的属性。

## 1. 值域必须有正向视觉语义

每个候选值都必须描述一个用户可以主动要求、偏好或讨论的视觉状态。不能把“没有某
物件”当成普通候选值，例如 `no milk foam`、`none`、`empty hands`、`no accessory`。
未提到某个可选物件，通常已经表示开放生成，不需要额外用一个“无”值占位。

优先使用具有实际视觉内容的等级、形态、材质、颜色、对象类型或关系状态，例如：

- `thin milk foam / moderate milk foam / thick milk foam`
- `dessert spoon / long-handled sundae spoon / flat tasting spoon`
- `thin crema / moderate crema / thick crema`

### 允许的例外

如果维度本身就是“数量、存在度、可见度、互动是否发生”等关系轴，缺失状态可以是
该轴不可避免的语义端点；但必须确认用户确实可能表达这个端点，且不能只是为了凑够
三个值而添加。此类例外应在属性说明中明确边界。

## 2. 手持物与非手持工具/设备必须分开

### 手持物

“手持物”只描述主体当前手中拿着、握着或操作的对象。它不是场景中所有物件的总表，
也不是某个职业的全部装备。若保留空手状态，必须有明确的关系轴理由，而不能把它当
作普通物件类别。

### 非手持工具或设备

“主要调查工具”“主要仪器”等非手持轴，只描述场景中可见的、承担该任务的具体工具
或设备，不要求主体当前拿在手里。值域必须：

1. 使用具体工具或设备类型，而不是“调查工具”“专业设备”这类上位词；
2. 三个值处于同一分类层级，不能混入证据、材料、人物角色或动作；
3. 不复制手持物的关系语义，不用“手拿着某物”作为值域定义；
4. 不使用 `none`、`no tool` 等缺省值；
5. 在属性说明中明确“场景中的工具/设备”与“主体当前手持对象”的边界。

例如，`Primary investigation tool` 可以使用放大镜、相机、电话这类具体工具；
`Evidence object` 则应只描述证据对象，不能混入调查工具。科学家的主要仪器与手持
样本容器也应遵守同一边界。

## 3. 同一属性只能有一条轴

不要在一个值域中混合“功能用途 + 装饰属性”“对象类型 + 是否存在”“物件类别 +
动作状态”。发现这种情况时，先拆轴或删除无效轴，再重新设计三个值。

## 4. 审核检查清单

逐个值检查：

- 用户是否可能主动说出或偏好这个值；
- 这个值是否有独立可见内容，而不是沉默的默认状态；
- 三个值是否同层级、互斥且覆盖合理范围；
- 是否与同组其他维度重复或构成上位/下位关系；
- 是否需要依赖另一个维度才能解释；若需要，说明中必须写清依赖边界。
